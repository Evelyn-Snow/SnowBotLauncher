# 小雪消息合流

把“连续发来的几句话”当成一段话理解，而不是一句一次请求。

## 解决什么问题

用户经常这样发消息：

```
这个视频讲了什么
好看吗
```

如果每条都单独进模型，她会先回“我看看”，再回“好看”，中间还可能因为工具执行
把后一句当成新消息，出现“你要发的东西没看到呀”这种割裂感。

这个插件在消息层的最前面（仅次于引用历史记录器）先收住消息，等一个很短的可刷新窗口，把同一 burst 的消息
合成一条，再重新交给 AstrBot 正常流程。

## 行为

1. 每条新消息把等待窗口刷到 `now + wait_seconds`，最长不超过 `max_wait_seconds`
2. 用轻量连续性评分决定要不要延长窗口：
   - 字面重合（中文 bigram Jaccard）
   - 追问开头（那/然后/所以/但是/还有/这个/怎么…）
   - 上一句没有句末标点（话没说完）
   - 同话题（视频/链接/看这个…）
3. 窗口结束后按连续性分组、按 `max_messages` 切块，逐块重新入队
4. `on_llm_request` 里合并历史中相邻的 user 消息，避免旧碎片继续干扰
5. 私聊和群聊都支持：
   - 实时合流只合并同一个发送者的连续消息，不同人各自成组
   - 群聊窗口更短（`group_wait_seconds=1.2`，上限 3 秒），避免 @ 后等太久
   - 合并时保留 At / 引用 / 图片 / 卡片，`@` 和引用仍能被识别
   - 群聊历史注入：带 `[时间] 昵称:` 标签的连续 user 消息可以跨人合并，标签保留；没有标签的不合并
6. webchat 默认不接管，避免影响网页 SSE；命令不接管

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| enabled | false | 总开关 |
| enabled_platforms | aiocqhttp | 生效平台，逗号分隔 |
| wait_seconds | 1.8 | 私聊基础等待窗口 |
| max_wait_seconds | 5.0 | 私聊连续追问最长等待 |
| group_wait_seconds | 1.2 | 群聊基础等待窗口 |
| group_max_wait_seconds | 3.0 | 群聊连续追问最长等待 |
| max_messages | 6 | 一次最多合几条 |
| continuity_threshold | 0.18 | 评分达到才延长窗口 |
| private_only | false | 保守开关：打开后不碰群聊 |
| group_enabled | true | 群聊也启用 |
| merge_history | true | 合并历史连续 user 消息 |

## 说明

- 单条消息也会等一个 `wait_seconds`，这是合流的成本；默认 1.8 秒，可调小。
- 命令（`/`、`！`）不接管，立即走原流程。
- 插件被禁用/重载时会把还没到时间的 burst 立刻放行，不会吞消息。
