# Bot 好友申请

自动处理好友申请，但**只同意看起来是真人的账号**——等级够高、开过会员、或是老号（短 QQ 号）。其余申请不主动处理，留在 QQ 的待处理列表里等人工。

## 判定顺序

```
黑名单         → 直接拒绝（附言可选）
白名单         → 直接同意
QQ 等级 ≥ 阈值 → 同意
会员账号       → 同意
QQ 号 ≤ N 位   → 同意（老号）
其余           → 挂起待人工
```

三档默认线：**等级 ≥ 16**（一个太阳）、**会员直接过**、**QQ 号 ≤ 9 位算老号**，三选一满足即可。

## 为什么这样判

| 信号 | 意义 |
|---|---|
| QQ 等级高 | 长期使用、有真实社交行为，批量小号很难养到 16 级 |
| 会员 | 付费账号，成本高，小号不会买 |
| QQ 号位数少 | 注册越早号越短，9 位以下基本是老用户 |

低等级 + 非会员 + 长号，绝大多数是临时注册的号，不适合直接放进好友列表。

## 其他保护

- **每日自动通过上限**（默认 5 个），超出后当天剩余申请一律挂起，防批量刷号
- 通过后**私聊告知主人**（发给谁、等级、昵称、申请附言）
- 黑名单可单独关闭「主动拒绝」，改成只挂起（不暴露"被拉黑"）
- 申请事件处理后**不会进入对话流程**，不会触发机器人乱回

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| enabled | true | 总开关 |
| min_qq_level | 16 | 等级下限，0 = 不看 |
| accept_vip | true | 会员直接同意 |
| max_qq_len | 9 | 位数 ≤ 此值算老号，0 = 不看 |
| whitelist / blacklist | 空 | 逗号或空格分隔的 QQ 号 |
| reject_blacklisted | true | 关闭后黑名单只挂起不拒绝 |
| max_accept_per_day | 5 | 每日自动通过上限 |
| notify_owner | true | 通过后通知主人 |
| owner_session | 空 | 通知发给谁，留空取 AstrBot 管理员 |
| reject_comment | 「暂时不方便加好友哦」 | 拒绝时的附言 |

## 依赖

- 纯标准库，无第三方依赖。
- 需要 NapCat 支持 `get_stranger_info`（查等级/会员）与 `set_friend_add_request`（处理申请），当前 NapCat 4.18.x 均支持。

## 注意

- 查不到申请者资料时（接口失败），按"等级 0、非会员"处理，也就是会挂起而不是盲目同意。
- 自动通过只在**收到申请时**生效，历史积压的申请需要手动处理。
